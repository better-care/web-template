### REA-008

**Заголовок:** Fix SCM url and ehr-common.version mismatch in pom.xml  
**Середність:** P2  
**Статус:** ПРОПОНУВАННЯ (не реалізовано)  
**Місцезнаходження:** `pom.xml` (рядки 36, 583-587)  
**Проблема:** `pom.xml` оголошує `version 6.0.0-SNAPSHOT`, але `ehr-common.version` — `5.0.0`, а URL SCM (`<url>https://github.com/better-care/web-template/tree/master/</url>`) вказує на `master/` без узгодження зі станом розробки SNAPSHOT. Це може спричиняти плутанину при релізах та збиранні.  
**Докази:** PR #9 відкрито на GitHub ("fix: SCM url + ehr-common.version mismatch (5.0.0→6.0.0-SNAPSHOT)"), рядки 36 та 583-587 pom.xml.  
**Причинний зв'язок:** Неузгодження між версією артефакту, версією залежності та URL SCM у момент підвищення до 6.0.0-SNAPSHOT.  
**Вплив:** Користувачі та інструменти релізу можуть вирішити неправильну версію ehr-common; SCM вказує на стабільну гілку, а код — SNAPSHOT.  
**Пропоноване виправлення:** Оновити `ehr-common.version` до версії, сумісної з 6.0.0-SNAPSHOT (або скорігувати версію артефакту) та узгодити URL SCM згідно з угодою проєкту.  
**Файли, що задіяні:** `pom.xml`  
**Тест валідації:** `mvn validate` (або `mvn dependency:resolve`) для підтвердження разрешення залежностей без помилки версії. Не може бути виконано локально (Maven не встановлено, Java 17 замість вимаганої Java 25).  
**Ризик змін:** Низький (зміна метаданих збирання, не логіки коду).  
**Польза:** Узгодженість збирання/релізу, уникнення неправильного разрешення залежностей.  
**Пропонований PR:** `fix: align ehr-common version and SCM url for 6.0.0-SNAPSHOT`  
**Пріоритет:** Невідкладний

### REA-009

**Заголовок:** Graceful handling of unmapped RM type in WebTemplateInputBuilderDelegator  
**Середність:** P2  
**Статус:** ПРОПОНУВАННЯ (не реалізовано)  
**Місцезнаходження:** `src/main/kotlin/care/better/platform/web/template/builder/input/WebTemplateInputBuilderDelegator.kt` (рядки 100-103 та 106-110)  
**Проблема:** `delegate()` використовує `requireNotNull(typeBuilders[...]) { "Unsupported type: ..." }`, кидаючи не оброблений виняток, коли тип RM не відображений у мапі `typeBuilders`. Немає резерву ani логаного повернення.  
**Докази:** Рядки 100-103: `with(requireNotNull(typeBuilders[RmUtils.getNonGenericRmNamePart(amNode.rmType)]) { "Unsupported type: ${amNode.rmType}" })`.  
**Причинний зв'язок:** Мапа `typeBuilders` не охоплює всі можливі типи RM; відсутність оброблення невідомих типів.  
**Вплив:** Збирання веб-шаблону ривково відмює для типів RM, що не відображені, без орієнтуючого повідомлення ani альтернативи.  
**Пропоноване виправлення:** Замінити `requireNotNull` на повернення `null` (або Optional-подібне), коли тип не відображений, дозволяючи викликачу вирішити (пропустити ввід, zalogувати попередження або кинути контрольований виняток).  
**Файли, що задіяні:** `WebTemplateInputBuilderDelegator.kt`, можливо `WebTemplateBuilder.kt` (викликач у `addInputs`).  
**Тест валідації:** Модульний тест, що передає `AmNode` з `rmType`, що не присутній у `typeBuilders`, та перевіряє, що не кидається не оброблений виняток. Не може бути виконано локально (немає збирання).  
**Ризик змін:** Низький (локалізована зміна в одному методі делегата).  
**Польза:** Міркування будувача для майбутніх або розширених типів RM; уникнення різкої відмови.  
**Пропонований PR:** `fix: handle unmapped RM type gracefully in WebTemplateInputBuilderDelegator`  
**Пріоритет:** Невідкладний

### REA-010

**Заголовок:** Validate divisor zero in path expression arithmetic operations  
**Середність:** P3  
**Статус:** ПРОПОНУВАННЯ (не реалізовано)  
**Місцезнаходження:** `src/main/kotlin/care/better/platform/web/template/path/evaluator/WebTemplatePathExpressionEvaluator.kt` (рядок 150)  
**Проблема:** Операція `DIV` (`left.toDouble() / right.toDouble()`) та `MOD` (`left.toDouble() % right.toDouble()`) не перевіряють, чи дільник дорівнює нулю. У Kotlin/Double ділення на нулю повертає `Infinity` або `NaN` без винятку, виробляючи тихо неправильні результати у клінічних виразах шляху.  
**Докази:** Рядок 150: `PathOperator.DIV -> left.toDouble() / right.toDouble()` та рядок 151: `PathOperator.MOD -> left.toDouble() % right.toDouble()`.  
**Причинний зв'язок:** Відсутність перевірки нульового дільника перед арифметичною операцією.  
**Вплив:** Вирази шляху з нульовим дільником повертають `Infinity`/`NaN` без явної помилки, що може генерувати неправильні клінічні дані без того, щоб користувач помітив.  
**Пропоноване виправлення:** Додати перевірку `if (right == 0) throw WebTemplatePathExpressionException("Division by zero")` перед операціями `DIV` та `MOD`.  
**Файли, що задіяні:** `WebTemplatePathExpressionEvaluator.kt`  
**Тест валідації:** Модульний тест оцінювання виразу `10 div 0` та перевірки, що `WebTemplatePathExpressionException` кидається. Не може бути виконано локально (немає збирання).  
**Ризик змін:** Низький (додавання перевірки в одній точці арифметичної операції).  
**Польза:** Предбачуваність і правильність клінічних виразів шляху; уникнення тихо неправильних результатів.  
**Пропонований PR:** `fix: validate divisor zero in path expression arithmetic`  
**Пріоритет:** Низький
