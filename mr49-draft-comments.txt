[Draft #18654] Line 494
  Malo pikolovsko, but fair point:

  **P1 [SEC] ReDoS vulnerability via user-supplied regex in `matches()` / `replaceMatches()`**

  `Regex(userInput).matches(...)` uses Java's `java.util.regex.Pattern` which
  is vulnerable to catastrophic backtracking. A pattern like `(a+)+b` evaluated
  against a long string causes exponential backtracking and can block a server
  thread indefinitely.

  If expressions are evaluated in a multi-tenant or server context, this is
  exploitable. Mitigations:
  1. Run regex matching with a timeout via a `Future` + thread interrupt, or
  2. Use a backtracking-safe engine (e.g. RE2/J), or
  3. Validate/reject patterns with known exponential constructs at parse time.

  At a minimum, add a Javadoc warning that untrusted expressions must not be
  passed to `evaluateExpression`.
