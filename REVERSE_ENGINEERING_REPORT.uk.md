## А. Загальний діагноз

### Виявлена архітектура
Проєкт `web-template` — це реалізація на Java/Kotlin для openEHR CDR (Clinical Data Repository). Конвертує Архетипи openEHR ( формат ADL/.opt) у WebTemplates (формат JSON) та виконує конвертацію клінічних даних між трьома форматами Представлення Моделлі (RM):

1. **RAW** — нативні об'єкти RM openEHR
2. **FLAT** — мапа шляху веб-шаблону → значення (згладжений формат)
3. **STRUCTURED** — ієрархічний JSON (структурований формат)

### Основні модулі (src/main/kotlin)
- `builder/` — будує WebTemplate з Template (откритий архетип openEHR). Точка входу: `WebTemplateBuilder.build()`.
- `converter/` — конвертери між форматами RAW/FLAT/STRUCTURED.
- `path/` — парсер та оцінювач WebTemplate Path Expression (на основі FHIRPath), використовуючи ANTLR 4.13.2 (граматика `WebTemplatePathExpression.g4`) + `WebTemplatePathExpressionFacade` + `WebTemplatePathExpressionEvaluator`.
- `model/` — `WebTemplate` (головний клас, серіалізація JSON через Jackson), `WebTemplateNode`, `WebTemplateInput`, діапазони появи.

### Технології та залежності
- Java 25, Kotlin 2.4.21, Maven (pom.xml)
- ANTLR 4.13.2 (граматика виразу шляху)

- Caffeine 3.3.1 (кеш)
- Бібліотеки openEHR common (ehr-common 5.0.0): model, utils, time, json-jackson, terminology, xml-jaxb, path, amnode

- JaCoCo 0.8.15, Sonar 5.8.0.7211 (покриття/якість)

## В. Повторні проблеми

Розробники вже намагалися виправити, але проблеми продовжуються/регресують:

1. **Дублювання ELEMENT/DATA_VALUE** — виправлено у 4.0.4 та 3.2.9, той самий текст виправлення. Свідczyть про відсутність тестів регресії, що б зашкодили поверненню.

## Г. Недокументовані помилки

Важливі помилки, виявлені цим аудитом, що не були задокументовані у проблемах/PR:

1. **Несумісність версії SCM/ehr-common** (PR #9 відкритий): `pom.xml` оголошує версію 6.0.0-SNAPSHOT, але `ehr-common.version` — 5.0.0, а URL SCM вказує на `master/` (навіть якщо master є реальною гілкою, версія здається непoslідною зі станом розробки).
2. **Тип RM не викликає не оброблений виняток**: `WebTemplateInputBuilderDelegator.delegate()` кидає `requireNotNull` з повідомленням "Unsupported type", якщо тип RM не у `typeBuilders`. Немає резерву або логаного оброблення.
3. **Тихе ділення на нуль** у оцінювачі виразів шляху: операція `div` з нульовим дільником виробляє `Infinity`/`NaN` без явного помилки, що може generaти неправильні результати у клінічних виразах шляху.
